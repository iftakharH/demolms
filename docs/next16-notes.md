# Next.js 16.4 cheat-sheet (demolms)

Compiled from the bundled docs in `node_modules/next/dist/docs/`. Doc tags are paths relative to
`01-app/`. Anything not verifiable in those docs is marked `UNVERIFIED`.

## 1. `cacheComponents` and `partialPrefetching`

- `cacheComponents` is a **top-level boolean** in `next.config.ts`; `false` (or omitting it) is a
  supported, valid setting and is the current 16.x default (source-verified: zod schema
  `cacheComponents: z.boolean().optional()` in `next/dist/server/config-schema.js`; internal TODO
  comment "Remove this once we've made Cache Components the default").
  (doc: 03-api-reference/05-config/01-next-config-js/cacheComponents)
- With `cacheComponents: false` you keep the **previous caching model**: `fetch` is NOT cached by
  default; you opt in with `cache: 'force-cache'`, `unstable_cache()`, or route segment configs
  `dynamic`, `revalidate`, `fetchCache`, `dynamicParams`.
  (doc: 02-guides/caching-without-cache-components)
- With `cacheComponents: true`: data fetching is **dynamic by default**; you opt into caching with
  `'use cache'`, `cacheLife`, `cacheTag`; PPR is on by default; and `dynamic`, `dynamicParams`,
  `revalidate`, `fetchCache` route segment configs are **removed** (build errors) — `experimental_ppr`
  was also removed. (doc: 03-api-reference/03-file-conventions/02-route-segment-config/index)
- `partialPrefetching` **requires** `cacheComponents`. Exact quote:
  > "`partialPrefetching` requires `cacheComponents`. Without it, `next dev` and `next build` throw at
  > config validation." (doc: 03-api-reference/05-config/01-next-config-js/partialPrefetching)

  Source-verified in `next/dist/server/config.js`: it throws only when `partialPrefetching` is truthy
  and `cacheComponents` is falsy. So with `cacheComponents: false` you must set
  `partialPrefetching: false` **or omit it entirely** (omitting is simplest).
- **Decision for this project**: omit both flags. The app is DB-backed and must always render fresh;
  classic dynamic rendering is simpler to reason about than `use cache` + `updateTag` everywhere.
- Note: with cacheComponents enabled, `cookies()`/`headers()` outside `<Suspense>` fail prerendering,
  and Cache Components requires the Node.js runtime.

## 2. Route segment config (previous model, `cacheComponents: false`)

Valid exports from `layout.tsx`, `page.tsx`, `route.ts`
(doc: 02-guides/caching-without-cache-components; 03-file-conventions/02-route-segment-config/index):

- `export const dynamic = 'auto' | 'force-dynamic' | 'error' | 'force-static'` (default `'auto'`)
  - `'force-dynamic'` = render per request
  - `'force-static'` = prerender; `cookies()`, `headers()`, `useSearchParams()` return empty values
- `export const revalidate = false | 0 | number` (seconds). `0` = always dynamically rendered, **not
  deprecated**. Must be statically analyzable (`60 * 10` is invalid).
- `export const runtime = 'nodejs' | 'edge'` — `'edge'` deprecated; default `'nodejs'`.
- Whether a **layout's** `dynamic` export is inherited by child pages: `UNVERIFIED` in the docs.
  Safest: put `export const dynamic = 'force-dynamic'` on the route groups that touch the DB.
- `unstable_noStore` is deprecated in favour of `connection()`.

## 3. Runtime APIs: `cookies()` and `headers()`

(doc: 04-functions/cookies, 04-functions/headers)

- `import { cookies, headers } from 'next/headers'`. Both **async** in 16; sync access fully removed.
- `cookieStore.get/has/getAll/set/delete`. Writable only in Server Actions and Route Handlers;
  Server Components may read only.
- Not allowed in Client Components. Using them opts the route into dynamic rendering.

## 4. Typed route helpers

(doc: 03-file-conventions/page, 03-file-conventions/layout, 03-file-conventions/route)

- `PageProps<'/blog/[slug]'>`, `LayoutProps<'/dashboard'>`, `RouteContext<'/users/[id]'>` are
  **globally available** (no import), generated by `next dev` / `next build` / `next typegen`.
- `params` and `searchParams` are **Promises**:
  ```tsx
  export default async function Page(props: PageProps<'/blog/[slug]'>) {
    const { slug } = await props.params;
    const query = await props.searchParams;
  }
  ```

## 5. Route handlers (`app/**/route.ts`)

(doc: 03-file-conventions/route; 01-getting-started/15-route-handlers)

- `export async function POST(request: Request, { params }: { params: Promise<{ slug: string }> })`,
  or typed with `RouteContext<'/users/[id]'>`.
- Default caching of `GET` handlers changed to **dynamic** in v15, so they run per request.
- Uploads: `const formData = await request.formData()`. Webhooks: `await request.text()` (verify HMAC
  over the raw text).
- File download: `new Response(new Uint8Array(bytes), { headers: { 'Content-Type': ..., 'Content-Disposition': ... } })`.

## 6. Server Actions / Server Functions

(doc: 01-directives/use-server; 01-getting-started/07-mutating-data)

- `'use server'` at the top of a dedicated file, or inline in an async function in a Server Component.
  Never inside a Client Component.
- Forms: `<form action={serverAction}>` receives `FormData`. **Re-check auth inside every action** —
  actions are reachable by direct POST and proxy matchers that skip a path also skip its actions.
- `useActionState` (React 19): `const [state, action, pending] = useActionState(fn, initialState)`.
- `redirect()` from `next/navigation` **throws** `NEXT_REDIRECT` — call it outside `try/catch`.
- Revalidation: `revalidatePath(path, type?)`; `revalidateTag(tag, profile)` — the 1-arg form is
  deprecated in 16 and produces a TS error (use `revalidateTag(tag, 'max')` or `{ expire: 0 }`).
  `updateTag()`/`refresh()` exist but are for the cache-components model.

## 7. `proxy.ts` (renamed from `middleware.ts`)

(doc: 03-file-conventions/proxy; 02-guides/upgrading/version-16)

- Location for a `src/` app: `src/proxy.ts`. Export `proxy(request: NextRequest)` (or default).
- **Runs on Node.js and the runtime is not configurable** — the docs state the `runtime` option throws
  in proxy files. So `better-sqlite3` session lookups are allowed here.
- Still not a full auth solution: docs recommend optimistic checks in proxy plus real checks in pages
  and server actions. This project does both.
- `config.matcher` must be build-time constants, e.g.
  `matcher: ['/admin/:path*', '/learn/:path*', '/dashboard']`.
- Server Function POSTs run on the page's own route, so a matcher excluding a path skips its actions.

## 8. Metadata & SEO

(doc: 04-functions/generate-metadata; 03-file-conventions/01-metadata/*)

- `export async function generateMetadata({ params }: PageProps<'/blog/[slug]'>): Promise<Metadata>`
  — `await params`.
- `openGraph: { title, description, images, url, type }`, `twitter: { card }`.
- `app/sitemap.ts`: `export default function sitemap(): MetadataRoute.Sitemap { return [{ url, lastModified, changeFrequency, priority }] }`.
- `app/robots.ts`: `export default function robots(): MetadataRoute.Robots { return { rules, sitemap } }`.

## 9. Fonts (offline-safe)

(doc: 02-components/font)

- `next/font/local` with `src` relative to the calling file:
  ```tsx
  import localFont from 'next/font/local';
  const instrument = localFont({
    src: '../fonts/InstrumentSans-Variable.woff2',
    display: 'swap',
    weight: '400 700',
    variable: '--font-instrument',
  });
  ```
  Note the family name next/font generates comes from the **variable name** (`--font-instrument` ->
  family `instrument`), and it also emits a metric-matched `"instrument Fallback"` next to it. The
  runtime stack is therefore `var(--font-ui)` in `globals.css`, which starts with
  `var(--font-instrument)` - do not hand-write `font-family: var(--font-sans)`, because `@theme inline`
  does not emit that variable (see the comment in `globals.css`; the symptom is a silent fall back to
  the system font).
- `next/font/google` **downloads at build time** and is therefore not offline-safe. Use local files.
  (This project self-hosts Instrument Sans in `src/fonts/`, fetched once by `scripts/fetch-fonts.mjs`.)

## 10. Navigation & errors

(doc: 04-functions/not-found, 04-functions/redirect, 03-file-conventions/error, loading)

- `notFound()` and `redirect()` both import from `next/navigation`.
- `app/error.tsx` must be a Client Component. **In 16 the prop is `retry`, not `reset`**:
  `export default function Error({ error, retry }: { error: Error & { digest?: string }; retry: () => void })`.
- Root layout errors need `app/global-error.tsx` (renders its own `<html>/<body>`).
- `app/not-found.tsx` and `app/loading.tsx`: default export, no props.

## 11. Other things that affect this build

- **`instrumentation.ts`**: `src/instrumentation.ts` exports `register()`, which Next calls **once per
  server process, before it handles requests**. It runs for every runtime, so node-only work must be
  guarded with `process.env.NEXT_RUNTIME === 'nodejs'`. This app uses it to apply the schema, run
  forward migrations and seed the demo data when the database is empty
  (`src/db/ensure.ts` -> `ensureDatabase()`), which is what makes a disk-backed deployment self-seeding.
  It is wrapped in try/catch on purpose: a read-only host should still boot and report errors per
  request rather than refuse to start.
- **Inline `<script>` in a layout**: put it in `<head>`, not in `<body>`. A script rendered as part of
  a component tree in the body logs "Encountered a script tag while rendering React component" as soon
  as that subtree re-renders on the client. The theme script (`src/app/layout.tsx`) lives in `<head>`
  for this reason, and `<html>` carries `suppressHydrationWarning` because the script sets
  `data-theme` before React hydrates.
- **`next/image`**: `images.domains` deprecated; local images with query strings need
  `images.localPatterns`. This project serves `/uploads/*` files with plain `<img>` tags, which need no
  configuration.
- **`next/link`**: prefetch is `"auto"` by default and only runs in production.
- **`useSearchParams`**: on a static page a client component using it must be inside `<Suspense>` or
  the build fails. `dynamic = 'force-dynamic'` pages avoid this; this project reads `searchParams` on
  the server instead.
- **`next/dynamic`** with `ssr: false` is not allowed in Server Components.
- **`after()`** from `next/server` schedules post-response work (used for audit entries where helpful).
- **`connection()`**: synchronous DB reads participate in prerendering, so a route that must read fresh
  data either uses `dynamic = 'force-dynamic'` or awaits `connection()` first.
- **Removed in 16**: `middleware.ts` (now `proxy.ts`), `next lint`, `serverRuntimeConfig`,
  `experimental_ppr`, `experimental.dynamicIO`; `runtime = 'edge'` deprecated; parallel route slots
  now require `default.js` (not used here). Turbopack is the default bundler; Node >= 20.9.
